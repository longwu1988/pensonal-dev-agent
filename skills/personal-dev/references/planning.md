# 建设与规格

空白工程先从整体需求确认用户、核心业务、应用范围、验收、部署约束与技术栈，再确定目录职责及环境。只创建已确定且需要的目录；不复制试点的四应用结构或历史版本。

既有工程先沿用稳定选型。技术调整记录原因、影响、迁移和验证，重要选择按下述统一提问策略取得决定后实施。

确定依赖安装、工具链与 CI/Docker 构建方式时，读取[依赖下载与镜像](dependency-downloads.md)，将适用的源配置纳入工程现有环境说明。

安排账号与环境时，按[凭据用途与来源](credentials.md)分别确定应用运行配置和 Agent 操作账号的来源；接入说明只记录来源，不集中复制真实值。

正式功能关联工程指定工单。新能力、业务规则、跨模块或 API 变化使用 OpenSpec：在 `openspec/changes/<change>/` 保存 proposal、design、tasks 和 specs；各产物分工，不在工单和另一套 plans 目录复制完整正文。工单保留诉求、验收与链接。

恢复已约定行为的局部 Bug 转实施流程，保留复现/修复/回归证据；发现规范本身需要变化才升级为规格变更。

新工程 Gitea/Drone 按确认技术栈配置 Tag 构建与产物，通过已授权的测试 Tag 验证后才记为接通。工程配置中用户明确确认的既有 Drone 集成直接沿用，不重新审计该流水线。

## 关键疑问先澄清

本规则贯穿接入、文档、原型与开发，不只用于新工程。

1. **尽早识别**：发现会影响范围、业务规则、权限、数据口径、验收或重要技术选择的疑问，先查当前对话、工单及适用规范。已有明确答案直接沿用；仍无法判断时，在定稿相关规格或开展依赖它的开发前向用户确认，不等到整套文档或代码完成才问。
2. **集中提问**：将当前已发现且需用户决定的问题按依赖关系归并，每题给出推荐答案、理由及主要影响；有合理备选时一并列出，避免逐条碎片追问。需要核实的事实提供推荐核实路径，不猜测事实作为答案。不要求一次预见所有后续问题；新增疑问发现后及时提出。遵循现有规范且不改变外部行为、范围或验收的命名、文件内组织等实现细节由 Agent 决定。
3. **等待期间**：可以只读调查、建立工单、记录待确认项、准备明确标为候选的方案或原型；也可继续已经授权且不依赖该决定的工作。未确认的假设不得写成正式结论，不定稿相关规格、不实施依赖它的业务代码。满足下述默认选择条件时，可按用户预先授权采用推荐方案；其他问题继续待确认。Figma、测试责任和方案审批等流程提问均适用统一策略；超时采用是用户预先委托的默认决定，不记为用户亲自验收或事实证明。
4. **决定后落实**：在现有工单或决策入口记录答案、范围及依据，区分“用户明确确认”和“按预授权超时采用推荐”，更新相关文档后继续，不新增重复报告、不重复询问同一已确认事项。已有文档不构成业务规则已获批准的证据。
5. **中途出现疑问**：暂停受影响部分，说明未知项及影响并澄清；保留独立工作进度。若新结论改变原有范围或已批准原型，按对应确认流程处理，不能用前一次确认覆盖新的决定。

## 提问推荐与三分钟默认选择

用户明确采用“所有问题均三分钟默认选择”后，所有工作流提问都采用本节，不再按 Figma、需求、选型、范围或验收类别设置“本题不适用”例外。仅安装 Skill 不构成这项授权；已有明确授权直接沿用。用户随后明确要求“必须等我回复”或暂停时尊重该次指令。

- **每题推荐**：给出明确推荐答案、理由、主要影响及“发送后 180 秒未回复将采用推荐继续”。推荐必须是当前授权和工具能力下可执行的下一步，不隐藏默认项、不事后补推荐。尚未生成原型、测试失败或证据不足时，推荐补齐或修复，不能推荐虚构通过。
- **全流程适用**：Figma 原型已生成且 Agent 视觉检查通过时，可推荐采用具体节点/版本进入开发，到期按预授权采用，无须再等待人工回复。用户自测待反馈时按[测试责任](testing.md)推荐转由 Agent 完成真实验证；默认选择不把未执行测试变成通过。重要选型、修改端和范围问题同样提出有依据的推荐并计时。
- **事实与操作边界**：缺少账号、环境或业务数据时，推荐可执行的核实路径，到期执行核实或推进独立部分，不猜测值。发布、部署、权限或数据操作须满足已有具体授权和宿主限制；没有条件时推荐安全准备、预览或核实步骤并按期执行，不把“全部提问”变成绕过宿主强制审批、禁止事项或数据破坏的授权。问题可到期选择下一步，实际前置条件仍需满足。
- **真实计时**：异步提问发送后记录每题发送时间、推荐内容与版本，截止为发送后 180 秒。使用可靠时间来源，不按工具调用次数、模型猜测或预选状态计时。等待时推进独立工作，单次等待工具不超过 60 秒，并处理新消息。
- **到期处理**：执行前检查最新回复、暂停及方案变化；真实满 180 秒且无答复时采用原推荐，简短告知用户并记录“按预授权超时采用”，随后继续依赖流程。明确答复优先；含糊答复继续澄清，不视为未回复。多题分别处理，不把部分回答推定为全部同意。
- **变化与续接**：用户要求等待、否定推荐或新信息使推荐失效时停止旧计时；重提推荐后重新计时。旧题若曾注明“不适用超时”或没有展示推荐，先按新规则重发，不能追溯认定已到期。恢复会话先核对新消息和原时间记录；不能证明计时、持续执行或访问所需工具时如实标记限制，不伪称已后台执行。

统一提示示例：“推荐采用原型 v1 进入开发，依据是……。3 分钟内未回复将按预授权采用此版本；你也可以提出修改或要求继续等待。” 全部题遵循同一计时策略；推荐动作是否成功仍由实际执行证据决定。本策略不自动创建后台调度或跨会话唤醒。
