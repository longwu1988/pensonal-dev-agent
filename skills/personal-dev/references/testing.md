# 测试责任与验收

## 选择模式

默认由 Agent 在任务 worktree 运行单元测试。用户明确“我来测试／我自己验收”时，该任务切为用户测试；不是全工程永久切换。将模式、任务分支、worktree 路径和待验收提交记录在工单中，不重复询问已明确的选择。

模式决定谁运行单元测试。整体构建、启动和关键路径由用户在代码合入集成分支之后自行验收。Agent 不把构建或运行冒烟当作 worktree 的完成条件，也不写成已经通过。缺少单元测试条件时如实报告阻碍，不把未运行的测试记为通过。

## Agent 测试（默认）

Agent 在保留本地改动的前提下进入任务分支或对应 worktree，对本次改动影响的代码运行单元测试，记录实际命令、提交、结果和缺口。到此为止：不执行构建、打包、启动服务、界面运行验收或集成冒烟。工程没有可运行的单元测试时，记录不适用及依据，并完成与改动相符的静态检查。

单元测试通过且审查无阻塞后，按[本机环境验证与集成](local-validation.md)串行合入工程配置的集成分支。这项流程里说的主分支，就是该集成分支。不额外等待用户再说“合并”。单元测试失败或尚未完成时留在该 worktree 修复，不合入、不关单。

## 用户测试（明确指定）

Agent 完成实现和代码审查，不运行单元测试、构建或替代性的业务验收；Git 状态、源码差异及提交核对仍执行。工单标注“待用户测试”，不能宣称单元测试已通过，也不提前合入、关闭。

交付时明确提醒用户切到哪个任务分支，提供 worktree 路径、提交、测试入口、覆盖点和预期结果。用户要求 Agent 帮忙切分支时直接执行并保留本地改动。

用户明确确认该提交的检查通过后，再进入串行合入。整体构建验收仍在合入之后由用户完成。按默认启用的一分钟策略，且没有明确关闭或必须等待约束时，反馈问题同时推荐“若 60 秒无回复，转由 Agent 完成该版本受影响代码的单元测试，通过后串行合入”，按[统一策略](planning.md#提问推荐与一分钟默认选择)展示并计时；到期只补跑单元测试。不得将沉默记为用户验收通过或构建已通过。用户新近要求“必须等我”或继续报告问题时尊重指令与失败事实，修复后重新提供推荐与验证安排。

## 合入与后续验收

按[本机环境验证与集成](local-validation.md)准备合并结果，并按[共享环境与合并排队](issue-claims.md#共享环境与合并排队)保证同一集成分支同时只有一个 worktree 在合入。目标更新或冲突处理改变代码时，重跑受影响单元测试，通过后再合入。合入记录写明构建与整体运行验收留给用户。必要单元测试未完成，或合并尚未按串行规则完成前，不更新远端集成分支，不关闭工单。
