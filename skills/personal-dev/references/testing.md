# 测试责任与验收

## 选择模式

默认由 Agent 测试。用户明确“我来测试／我自己验收”时，该任务切为用户测试；不是全工程永久切换。将模式、任务分支、worktree 路径和待验收提交记录在工单中，不重复询问已明确的选择。

模式决定执行责任，不改变验收条件。缺少环境、平台或必要证据时如实报告阻碍，不自动把未完成测试视为通过。

## Agent 测试（默认）

Agent 在保留本地改动的前提下自动切换到任务分支或进入对应 worktree，核对实际服务目录、端口和运行代码。分支切换与服务启停分别受授权约束；工程禁止启停服务时仍遵守，不能因自动测试而自行重启。

按影响运行测试、构建及必要的平台检查，记录实际命令、提交、结果和缺口。测试通过且审查无阻塞后执行[交付流程](delivery.md)，不额外等待用户再说“合并”。失败或未完成时继续处理，不能合并或关单。

## 用户测试（明确指定）

Agent 完成实现和代码审查，不运行自动测试、构建或替代性的业务验收；Git 状态、源码差异及提交核对仍执行。工单标注“待用户测试”，不能宣称已测试通过，也不提前合并、关闭。

交付时明确提醒用户切到哪个任务分支，提供 worktree 路径、提交、测试入口、覆盖点和预期结果。核对已知运行目录，指出需要配套运行的前端/H5/后端；不能仅提示刷新页面而让用户测试旧主分支。用户要求 Agent 帮忙切分支时直接执行并保留本地改动，按工程规则由用户启停服务。

用户明确确认该提交通过后直接收尾。已采用全量三分钟策略时，反馈问题同时推荐“若 180 秒无回复，转由 Agent 完成该版本的真实测试及视觉验证，通过后收尾”，按[统一策略](planning.md#提问推荐与三分钟默认选择)展示并计时；到期可切换并记录测试责任，再实际执行必要测试。不得将沉默记为“用户验收通过”，测试未做、失败或环境缺失时不合并关单。用户新近要求“必须等我”或继续报告问题时尊重指令与失败事实，修复后重新提供推荐与验证安排。

## 合并时的证据有效性

核对最新目标分支、已测试提交及合并结果。合并后代码树与验收版本一致时保留原测试证据，核对本地与远端提交即可，不重复测试。若目标更新或冲突处理改变了待交付代码，按同一测试模式补验：Agent 模式由 Agent 测试，用户模式交回用户复验，并按上述反馈策略处理；通过前不推送集成结果或关闭工单。必要时先在隔离的临时集成分支处理和验收。
