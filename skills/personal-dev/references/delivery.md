# 交付流程

重要业务变更需要独立审查上下文；无子代理时使用独立会话或人工审查，执行者自查不计为独立审查。按工程规则完成验证后，按已有授权推送任务分支、创建 PR、回写任务关联工单；未验证项明确列为缺口。

合并集成分支需要该任务的明确指令或预授权。核对审查的提交和最新目标分支；同步与解决冲突后重新验证受影响范围，合并提交，不复制 worktree 目录。

合并后执行集成回归，满足验收才关闭工单。集成回归失败时报告失败、保持任务未完成并处理修复；用户催促交付不能将失败改写为通过。

打包独立于合并。依据用户指令或预授权，在确认且验证通过的提交上创建并推送 Tag 到 Gitea，由 Drone 构建。仅有本地 Tag 不算触发；检查本次构建状态和产物。用户已确认的现有 Drone 配置不重新核查。发布 Tag 不任意移动，生产部署另按授权执行。

交付记录保留后，核查 worktree 内未提交和未推送内容及引用，再按工程约定清理。知识与规则变更需人工审查；当前安装器不启用夜间任务，也不自动发布复盘结论。
