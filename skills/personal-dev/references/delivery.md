# 交付流程

用户验收回复、Git 提交/推送/合并和中断续接均先按[收尾记录与完成检查](completion.md)恢复关联工单，保存阶段并检查最终结果；普通工单与队列共用。

## 自动收尾的授权与条件

用户明确将“测试通过后自动合并、提交推送、关闭工单”作为工程常规流程时，按[权限与作用域](permissions.md)记录已明确授予的长期动作，含任务分支推送、创建 PR、工单回写、关闭及合入指定集成分支；占用与标签另按控制授权核对。已有明确授权沿用，不重复逐项批准。仅针对当前单的决定写本 owner/issue 记录，不提升为工程长期授权；当前 deny/撤销始终优先于旧授权。仅安装本 Skill 不构成外部操作授权，未采用此流程的工程仍按实际授权处理。Tag、部署及服务启停不在这项授权中。

完成条件按[测试责任与验收](testing.md)判断：默认是受影响代码的单元测试通过后收尾；用户测试模式按测试责任取得该提交的确认后收尾。整体构建验收由用户在合入后进行，不作为本步门槛。重要业务变更仍需独立审查；无子代理时使用独立会话或人工审查，执行者自查不计为独立审查。

## 合并、推送与关单

先按[工单隔离](issue-claims.md#共享环境与合并排队)核对本 owner。单元测试证据覆盖候选代码树后进入 ready_to_merge。取得目标分支集成锁进入 merging 后才执行远端合并或集成分支推送，其他 worktree 保持等待。没有另行要求操作共享运行环境时，不申请 environment 锁，也不启动服务。锁不代替权限、单元测试或分支保护。

先读[PR 合并方式与证据](pull-requests.md)：默认 PR，只有工程或用户明确选择才直接合并；已有明确选择保留。方式不扩大授权。Agent 每次业务 push、PR 写入、合并、工单评论和关闭前，除 queue-guard 外执行对应 [permissions-check](permissions.md#每次外部写入前检查)；CLI 不自动执行这些动作。

1. 保存实现和证据到任务提交；按选定方式和授权推送任务分支、创建或复用 PR，并回写关联工单。单元测试尚未通过时明确标注待 Agent 测试或待用户测试，代码写完不等于可以合入。
2. 按[本机环境验证与集成](local-validation.md)核对最新集成分支和已通过单元测试的提交，准备合并结果。单元测试失败或冲突未解决时留在任务分支修复，不推进远端集成分支。不在这一步执行构建或运行冒烟。
3. 单元测试证据覆盖候选代码树后，记录同提交 accepted/integration_verified 并进入 ready_to_merge。`integration_verified` 在这里表示串行合入前的代码树核对，以及构建验收留给用户；申请 merging 成功后再次核对目标未变化，按选定方式及授权合并 PR 并读回合并结果，或在明确的直接合并模式推送集成分支。同一集成分支同时只合入一个 worktree。PR 模式必须先让单元测试覆盖本地合并候选，不能等远端合并后才第一次跑单元测试。
4. 同步本地集成分支与远端。本单未切换运行环境时记录未改动；改过则先恢复。工单写明单元测试结果、合并提交与 PR，并写明构建与整体验收留给用户，再按[完成检查](completion.md#回写关闭和恢复)关闭并读回远端状态。推送失败、锁未释放或单元测试证据缺失时保持开放。

收尾结果用 queue-finish 核验并同步 ai-done；尚有步骤缺失时保留原占用，不因已关闭、已 push 或标签错误而重新开发。

不能停在“代码已写好”“PR 已创建”或“push 已成功”就宣称任务完成；已获完整授权的常规任务应完成测试、合并、远端同步和关单链路；当前授权限定本地或控制操作时报告已完成部分和被禁止的待办，不为达到完成状态扩大权限。

## 打包与 CI 选型

打包方式按工程需求选择，**Drone 是可选建议，不是个人智能体接入、开发、合并或验收的必需项**。新工程先核对交付目标、现有基础设施和客户偏好；可提示“Drone + Tag 自动打包”这一模式，并说明其他 CI、人工/本地打包或当前无需打包同样可选，不默认安装 Drone 或创建流水线。已有明确方案直接沿用；尚未选择时在需要打包前按[澄清规则](planning.md#关键疑问先澄清)确认，不阻塞独立开发。

在工程 `delivery` 配置记录方案、触发方式、验证状态与依据：`provider` / `trigger` 默认 `null` 表示待选择；`provider: "manual"` 表示人工打包，`"none"` 表示当前不需要打包，其余使用实际 CI 名称。触发方式可以是 Tag、分支、手动或项目约定值；不适用时为 `null`。旧模板自动生成的 `drone/tag` 且没有选择依据，不当作用户已经选择；升级保留原配置，实际需要打包时先核对并记录决定。用户已确认的既有方案（包括 zkxw 的 Drone）沿用，不重复审计或擅自迁移。

仅在工程选定自动构建时配置其 CI，按已授权的实际触发方式验证构建状态和产物可获取后才记为接通；人工打包验证命令与产物，不为完成通用流程额外要求 CI 或测试 Tag。`none` 可记录 `not-applicable`，不把未启用 CI 记为接入失败。选择方案不自动授予推送 Tag、部署或服务启停权限。

## 发布与清理

打包独立于合并。依据工程已选方案和用户指令或预授权，对确认且验证通过的提交执行对应构建，记录提交、触发方式、结果和产物位置；无需打包的任务不强制触发。工程选择 Tag 触发时才按授权创建并推送 Tag 到对应仓库，由所选 CI（如 Drone）构建，核对本次流水线与产物；仅有本地 Tag 不算已触发远端构建。发布 Tag 不任意移动，生产部署另按授权执行。

关单读回及完成检查成功后，按[worktree 生命周期](worktree-lifecycle.md)保存恢复信息、检查全部文件与占用，清理本任务 worktree 并记录结果；符合条件的目录及时回收，本地任务分支默认保留至少 7 天。阻塞、待用户测试、停止和来源不明项保留，不以日期或数量强删。知识与规则变更需人工审查；当前安装器不启用夜间任务，也不自动发布复盘结论。
