# 交付流程

用户验收回复、Git 提交/推送/合并和中断续接均先按[收尾记录与完成检查](completion.md)恢复关联工单，保存阶段并检查最终结果；普通工单与队列共用。

## 自动收尾的授权与条件

用户明确采用“测试通过后自动合并、提交推送、关闭工单”流程，即为当前工程常规任务的持续授权，包含任务分支推送、创建 PR、工单回写及合入已指定的集成分支。记录该授权，沿用已有决定；不能再要求用户逐项批准。仅安装本 Skill 不构成外部操作授权，未采用此流程的工程仍按实际授权处理。Tag、部署及服务启停不在这项授权中。

完成条件按[测试责任与验收](testing.md)判断：默认 Agent 测试通过即收尾；用户测试模式按测试责任中的反馈/默认转测流程取得真实通过证据后收尾。重要业务变更仍需独立审查；无子代理时使用独立会话或人工审查，执行者自查不计为独立审查。

## 合并、推送与关单

1. 保存实现和证据到任务提交；按授权推送任务分支、创建或更新 PR，并回写关联工单。未完成测试时明确标注待 Agent 测试或待用户测试，修复实现完成不等于验收通过。
2. 按[本机环境验证与集成](local-validation.md)核对最新主分支和验收提交，准备合并结果，完成适用的集成环境冒烟；失败在任务分支修复，保留现场，不推进远端主版本。
3. 必要验证通过或明确不适用后，核对目标未变化，再按授权推送集成分支或合并 PR；PR 模式必须先验证本地等价候选，不能等远端合并后才首次验证。
4. 同步本地主分支与远端，按本机验证流程完成运行环境恢复及版本核对。证据覆盖最终代码和实际环境后，在工单记录测试责任、验收/冒烟结果、合并提交与 PR 并关闭，按[完成检查](completion.md#回写关闭和恢复)读回远端状态；推送失败、环境恢复未完成或验证缺失时保持开放。

不能停在“代码已写好”“PR 已创建”或“push 已成功”就宣称任务完成；常规任务应完成测试、合并、远端同步和关单的完整链路。

## 打包与 CI 选型

打包方式按工程需求选择，**Drone 是可选建议，不是个人智能体接入、开发、合并或验收的必需项**。新工程先核对交付目标、现有基础设施和客户偏好；可提示“Drone + Tag 自动打包”这一模式，并说明其他 CI、人工/本地打包或当前无需打包同样可选，不默认安装 Drone 或创建流水线。已有明确方案直接沿用；尚未选择时在需要打包前按[澄清规则](planning.md#关键疑问先澄清)确认，不阻塞独立开发。

在工程 `delivery` 配置记录方案、触发方式、验证状态与依据：`provider` / `trigger` 默认 `null` 表示待选择；`provider: "manual"` 表示人工打包，`"none"` 表示当前不需要打包，其余使用实际 CI 名称。触发方式可以是 Tag、分支、手动或项目约定值；不适用时为 `null`。旧模板自动生成的 `drone/tag` 且没有选择依据，不当作用户已经选择；升级保留原配置，实际需要打包时先核对并记录决定。用户已确认的既有方案（包括 zkxw 的 Drone）沿用，不重复审计或擅自迁移。

仅在工程选定自动构建时配置其 CI，按已授权的实际触发方式验证构建状态和产物可获取后才记为接通；人工打包验证命令与产物，不为完成通用流程额外要求 CI 或测试 Tag。`none` 可记录 `not-applicable`，不把未启用 CI 记为接入失败。选择方案不自动授予推送 Tag、部署或服务启停权限。

## 发布与清理

打包独立于合并。依据工程已选方案和用户指令或预授权，对确认且验证通过的提交执行对应构建，记录提交、触发方式、结果和产物位置；无需打包的任务不强制触发。工程选择 Tag 触发时才按授权创建并推送 Tag 到对应仓库，由所选 CI（如 Drone）构建，核对本次流水线与产物；仅有本地 Tag 不算已触发远端构建。发布 Tag 不任意移动，生产部署另按授权执行。

交付记录保留后，核查 worktree 内未提交和未推送内容及引用，再按工程约定清理。知识与规则变更需人工审查；当前安装器不启用夜间任务，也不自动发布复盘结论。
