# 界面一致性、原型与验收

适用于界面设计、原型生成、界面实现和布局样式修改，包括只做 Figma 设计、临时 HTML 预览或用户明确免除原型后的直接编码。在调用设计/生成工具前就读取本规则，不等业务实现时再补参考。只要求设计时保持设计范围，不因此开始业务开发。新页面、新弹窗及用户要求的视觉改版须经过下述 Figma 确认；纯文案纠错、无视觉变化的后台逻辑和恢复已确认设计的局部修复不新增原型，按影响验证。

## 先确定视觉依据

已有工程默认延续目标应用现行风格。新增页面或“美化一下”本身不代表重做全站视觉；已有明确改版决定时按其范围执行。先完成以下核对，再开始画原型或生成界面：

1. **定位现行规则与代码**：查目标端规则、UI 规范、布局壳、组件目录、主题与 Token 配置，以及同类页面的实际调用。确认当前主题、组件变体和局部样式覆盖；不能只读框架名称或默认组件文档，就把库的默认样式当成工程风格。
2. **查看同端同类实际界面**：优先选一个最接近本任务的页面或组件，必要时补充参考，不要求扫描全站。区分确认提示、表单编辑、选择器和详情，不能只因名称含 Dialog 就套用。工程已在运行且允许查看时，先核对访问地址、路由、应用和可确定的运行版本，再按[测试责任](testing.md)查看实际效果；记录视口、主题、代表状态及截图或其他可回看的视觉证据。未知版本明确标注，不把其他应用、旧构建或设计稿冒充当前界面。不为取参考擅自启停或重启服务；环境操作遵循[本机环境规则](local-validation.md)。
3. **提取复用决定**：将布局与信息密度、导航/页头、字体层级、颜色、间距、圆角、边框/阴影、图标，以及受影响控件的尺寸与状态，映射到实际组件、变体和 Token 来源。只记录本任务相关项；没有 Token 的工程引用有效样式定义，不强制先建设设计系统。优先复用完整组件，能力缺口明确时才局部扩展或新增，不复制一组 CSS 后混搭默认控件。
4. **处理差异与缺口**：已明确的任务决定和工程现行规范共同限定范围；旧页面、旧 Figma 与旧 Token 都须核对适用性。存在多套风格时优先采用目标模块现行规范及有效参考，不从其他端随意混搭。无法判断且会影响设计时，只询问具体差异；无关部分可继续。新工程无参考时建立候选视觉方向并按原型流程确认，不能把已有工程误当空白工程自由发挥。

在现有工单、设计记录或本次任务上下文中留下简短“视觉依据”，并在设计前向用户概述参考与复用选择，不另开一轮批准或新增永久报告。至少可追溯到：参考路由/页面/节点与视觉证据、组件和主题/样式路径、本次保留的特征、必要差异及原因、尚未验证项。单写“保持现有风格”不算完成。已有同任务证据仍适用时直接复用，主题、范围或版本改变后只补核对受影响部分。

无法访问运行界面时，先利用已有可信截图、组件示例和代码查证，并说明未观察的部分。用户自测或禁止 Agent 浏览/运行时遵守限制，使用已有材料或交付需要用户核对的项目，不擅自转成 Agent 测试。已有证据足以支持的设计可继续，不能声称已完成实际对照；关键风格无法确定时暂停依赖该选择的设计，只补必要信息，不用通用模板填补未知。

### 把视觉依据传给设计工具

向 Figma、其他已授权的设计/生成工具或执行者交接时，带上上述参考及复用映射、保留项和允许变更范围，不能只传业务需求或一句“现代简洁”。使用目标工具实际可访问的节点、素材或脱敏视觉说明；不可访问的链接不当作已读。参考采集不授权把运行中的业务数据上传到外部工具。

Figma 有匹配的组件库、变量或样式时优先复用并核对与当前工程的一致性；只有代码资产时，据已查证的视觉依据构建可编辑原型并保留映射，不虚称已经导入组件库。其他工具及直接编码沿用相同依据；更换工具或免除 Figma 不免除风格继承，也不自动替代下述 Figma 原型要求。跨端共享业务语义，各端保留其已确认设计体系。

## 先设计，再实现

1. 按上述步骤确定视觉依据与影响范围。简单、单字段、已有匹配组件或时间紧，都不免除本流程；复用资产应体现在原型中。
2. 使用 Figma MCP 创建可编辑原型，覆盖任务涉及的主要尺寸、输入、加载、错误和提交状态。检查文字、间距、按钮、滚动及安全区，并与选定的同端参考对照风格；修正未经决定的偏离后，向用户提供具体文件/节点链接和可查看的预览。展示复用依据及有意差异，不能把“Figma 生成成功”当成风格一致的证据。
3. 在工单或工程指定的设计入口记录原型链接、版本及“待原型确认”。原型完成并通过视觉检查后，给出采用该版本或修正问题的推荐，按[统一一分钟策略](planning.md#提问推荐与一分钟默认选择)处理；用户选择或满足默认策略条件到期采用后可进入业务界面实现，不再把原型列为必须人工回复的例外。记录具体版本与决定来源，已有同版决定直接沿用；工具生成成功本身不算验收。
4. 将原型元素映射到已选组件、变体和 Token，按确认的原型实施并完成下述视觉验收。若后续明显改变布局或交互，更新原型并按同一策略重新提交受影响部分；原型确认不替代最终功能验证。

为制作原型生成的临时 HTML 或设计脚本存放在工程规定的临时目录，不作为已经批准的业务实现提交。

## 唯一默认豁免

用户明确表示本任务“不用生成 Figma 原型”或同等意思时，记录原话含义、任务和范围后直接继续，不重复请求同一豁免；仍遵循视觉规范、必要澄清与最终验证。豁免仅限明确范围，不推广到后续任务。

用户只说“赶时间”“复用现成弹窗”“代码完成再验收”，不能推断为不用 Figma。提供具体原型后按统一策略决定是否采用；未生成原型不能先完成业务代码再补图。

Figma 连接或权限不可用时，说明实际阻碍，继续独立工作；推荐恢复连接或推进独立工作并按统一策略执行；依赖原型的实现保留实际缺口，不把其他工具截图称为已完成 Figma 原型。跳过原型需用户已明确免除，自动采用原型不等于免除制作原型。

## 实现后的视觉验收

按[测试责任](testing.md)执行：worktree 内以受影响代码的单元测试为完成条件。实现时对照已确认原型、同端参考、组件和主题做源码级核对，列出布局、层级、字体、间距、颜色、按钮主次和受影响状态上的对应关系。不为此构建、启动应用或截取运行界面。运行后的整体视觉验收由用户在合入后的集成分支上完成；工单保留需要用户看的核对点，不把源码对照写成运行界面已经通过。

实现偏离已确认设计时先修复；设计本身需要改变时按原型确认规则处理。新原型若已偏离现行风格且没有对应改版决定，先纠正设计，不能因为实现与该原型相同就判定一致性通过。明确免除 Figma 只省去原型，不省去视觉依据和组件复用。运行后的效果由用户在合入后的集成分支上验收。

## 将有效设计留给下一次任务

验收通过后在工程现有模式索引中记录“适用交互、组件/页面路径、设计依据、关键状态及限制”；没有索引时在现有 UI 规范入口保留简短引用。业务尺寸和色值留在工程，个人 Skill 只沉淀方法。首次实现可作为局部参考；出现多个真实复用点且接口稳定时再提取共享组件，迁移已有页面单独确认范围，不借单个弹窗任务全仓替换。
