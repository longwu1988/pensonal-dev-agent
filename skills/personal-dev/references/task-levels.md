# 任务级别与加载预算

协调者在读取完整流程表之前，先用本条消息和已有任务证据判定级别。入口与 Cursor 适配器只保留判定摘要；本文件是级别、上调与加载预算的权威来源。

## 级别判定

| 级别 | 何时选用 | 必做 | 明确不做 |
| --- | --- | --- | --- |
| **L0 咨询** | 解释、定位、对比方案；不改仓库行为；不创建工单交付 | 直接答复；必要时只读相关代码或配置 | 不读完整流程表；不做版本升级决策；不占用、不建 worktree、不走 Figma、不适用一分钟确认；不问修改端 |
| **L1 轻量** | 范围明确的单点修复或小改：文案、配置、局部逻辑、有明确同类参考的界面微调；不改业务规则、跨模块 API 或架构 | 影响检查；只打开本级允许的引用；有工单编号则领取后修改；最小验证；用户明确要求提交/合入/关单时才走收尾 | 不建 OpenSpec 全套；不强制新建 worktree（可复用当前会话已有任务目录或分支）；无编号的明确小修可不建完整规格；不默认翻完全部评论，除非续接已关联正式单 |
| **L2 正式** | 新能力、跨模块、规则或 API 变化、空白工程或技术栈变化、正式工单开发交付、用户要求完整流程 | 沿用实施 → 测试 → 交付主链；按入口分支表按需加载 | 仍保持每阶段一个主流程，不串联全部上游技能 |

边界不清时取较高一级：例如“顺便解释一下再改一处”按 L1；已给出正式工单编号且要求开发交付按 L2。

## 上调与下调

执行中发现跨端范围、业务规则或 API 变化、无可用来源界面参考、标准冲突须先定口径、或验收条件不清时，升到 L2，或按[界面规则](ui-design.md#是否需要-figma-原型)触发 Figma，并简短告知用户。

不得因“赶时间”“先写代码再看”下调级别。用户明确把范围缩到单点且证据充分时，可从 L2 降到 L1，并记录新依据。

## 入口加载预算

1. **先分级**，再决定是否打开流程引用。
2. **L0**：直接答复后结束；可不读 `project.json` 全量字段，也不调用版本检查。
3. **L1 / L2**：再读根 `AGENTS.md` 与 `docs/agents/project.json` 的当前阶段必要字段；只打开该级允许的 references。
4. **版本检查**：仅新任务首次且已进入 L1 或 L2 时按[更新规则](updates.md)执行；同一任务续聊不重复；L0 不做。
5. **关键澄清与一分钟策略**：仅适用于 L1 / L2 中会影响范围、规则、验收或重要选型的决定；L0 不适用。细则见[建设与规格](planning.md#关键疑问先澄清)。

## 按级允许读取

| 引用 | L0 | L1 | L2 |
| --- | --- | --- | --- |
| 本文件（判定后可不再重读） | 判定时 | 是 | 是 |
| [实施流程](implementation.md)（含 L1 短路径） | 否 | 是 | 是 |
| [界面一致性、原型与验收](ui-design.md) | 否 | 涉及界面时 | 涉及界面时 |
| [测试责任](testing.md) | 否 | 改代码时 | 是 |
| [工单占用与隔离](issue-claims.md) | 否 | 有编号或需领取时 | 正式工单必读 |
| [工单全文、评论与图片](issue-context.md) | 否 | 有编号时读正文与当前相关评论；不默认全量翻完 | 正式单全文、评论与图片 |
| [建设与规格](planning.md) | 否 | 仅关键未知时相关节 | 空白工程、大需求、规格变更 |
| [权限与作用域](permissions.md) | 否 | 平台写入或权限变化前 | 工单启动/恢复及写入前 |
| [交付](delivery.md) / [收尾](completion.md) / [PR](pull-requests.md) | 否 | 用户明确要求交付时 | 是 |
| [Worktree](worktree-layout.md) / [本机验证](local-validation.md) | 否 | 需要新建隔离或合入时 | 是 |
| 队列 / 持续检查 / 更新 | 否 | 用户点名时 | 用户点名或正式单需要时 |

队列启停、持续监听与 worktree 巡检本身按用户指令进入对应引用，不受 L0 咨询路径吞掉；它们不是“概念问答”。
