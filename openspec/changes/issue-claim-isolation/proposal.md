# 工单级占用与多会话处理

## Why

现有全仓队列锁只能拒绝第二个会话，普通工单入口也不共用领取机制。用户已确认改为工单级原子领取、八种可见状态、多会话独立执行和串行合并。

## What Changes

- 远端 Git CAS 工单记录作为占用和完成依据，独立会话状态保存在工程忽略目录。
- 队列、指定编号与持续检查共用领取入口；停止保留占用，接管须核对原会话停止。
- GitHub/Gitea 状态标签自动创建、同步并读回，不覆盖业务标签。
- 集成分支和共享本机环境的独占操作需单独获取资源锁。
- 协议升为 5，旧版活动队列必须先收尾，完整源码迁移保留状态；旧执行器由兼容哨兵拒绝进入。

## Impact

新增 issue_claims / issue_workers 运行时；更新 CLI、标签客户端、watch 接入、分发和规则。仅验证本地合成仓库及 API 响应，不操作真实业务工单或启停服务。
