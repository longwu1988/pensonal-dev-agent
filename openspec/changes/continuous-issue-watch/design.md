# 持续工单检查增量规范

## 问题与设计

一次性队列在空队列时释放锁并退出，没有未来唤醒或可撤销的持续授权。增加独立 Watch 状态模块，复用 Queue 的 Git 占用、工单筛选、上下文读取和收尾检查。宿主定时任务负责唤醒同一 Agent 会话；脚本负责授权代次、绑定、间隔和停止校验，不内置模型执行器。唯一操作规范为 [issue-watch.md](../../../skills/personal-dev/references/issue-watch.md)。

## 要求

- 默认关闭；仅用户明确的持续指令授权。普通队列仍处理完退出。推荐 300 秒、ai-ready；不将未来工单解释为全部开放工单。
- 开启经历 pending → 绑定真实宿主计划 → active，并由宿主激活读回与首次检查验证。没有宿主能力不能报告已运行。
- Tick 校验工程、分支、原生调度 ID、同会话 ID、代次与停止令牌。独立 owner 防止旧执行者沿用新授权；本机锁和持久 next_due 抑制重复调用，远端 Git lease 防跨机器重复领取。宿主保证业务执行串行，不宣称 CLI 的短命令锁覆盖整个开发周期。
- 当前单优先；空队列释放 Git lease，保留持续授权，下次可以领取新单。等待用户不得推定验收通过；完整评论和图片、worktree、验证、合并及关单要求不变。
- 用户停止先落盘撤销令牌，再暂停原生计划。旧唤醒、换代旧 ID、手动 queue-start 均不能重建被撤销持续授权。授权校验与 queue-start 之间的停止竞态必须拒绝。
- 错误不视为空，失败退避并在连续三次失败后暂停；权限或绑定变化立即停下核对。无 TTL 抢锁，不删除未完成工作。
- 新模块采用分发协议 3，旧协议 1/2 必须完整源码迁移。保留配置及本地状态，恢复不依赖旧模块白名单。升级不自动创建计划或扩大授权。

## 验收边界

合成测试覆盖默认关闭、空队列后新增、重复唤醒、停止竞态、旧代次、用户等待、占用冲突、失败退避、CLI 安装和跨协议恢复。行为测试核对宿主接入与无调度工具的处理。真实 Codex heartbeat 持续运行和 Cursor 调度尚未验收，本轮不替真实工程开启任务。
