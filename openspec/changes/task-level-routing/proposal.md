# 任务分级与 Figma 触发收紧

## Why

个人智能体对简单问答与复杂开发共用一条重流程：Cursor 入口 alwaysApply 指向完整 Skill，级别只有口头“纯咨询可跳过”，没有可执行判定与加载预算。结果是解释类问题与单点小修也容易串进占用、全文工单、改端确认、worktree、Figma 与一分钟确认，消耗过多上下文。试点曾收紧为“单字段也要 Figma”，现需在保留复杂界面保底的前提下，按参考与标准一致性分流。

## What Changes

- 新增 L0 / L1 / L2 任务级别、上调规则与按级加载预算；入口先分级再读引用。
- L0 直接答复；L1 走实施短路径；L2 保持正式实施 → 测试 → 交付主链。
- Figma 仅在无可用同端参考、同端标准不一致且须先定口径、或客户/用户明确要求时强制；有参考且标准一致可跳过原型，仍须视觉依据与一致性核对。
- 一分钟推荐选择与确认语音仅适用于 L1 / L2 的关键决定。
- Cursor adapter 内嵌级别摘要，避免 L0 先读完整 Skill。
- 增补[题型剧本](../../../skills/personal-dev/references/playbooks.md)：按问题类型（咨询/定位/单点修补/带编号小 Bug/界面微调/正式功能/仅交付）分流；L1 实施抽到独立 `implementation-l1.md`；短剧本跳过新任务版本检查并设硬加载上限。

## Impact

Skill 入口、Cursor 适配、实施/界面/规划/角色引用、使用指南与行为案例；OpenSpec 以本变更修订开发与交付中的轻量任务与 Figma 要求。不改队列/占用协议、不削弱正式单领取与默认 PR 合并，不引入 token 计量服务。真实 Codex/Cursor 会话省 token 效果仍待试点观察。
