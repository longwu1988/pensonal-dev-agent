## ADDED Requirements

### Requirement: 任务先分级再加载流程

体系 SHALL 在读取完整开发流程表之前，按 [任务级别与加载预算](../../../../../skills/personal-dev/references/task-levels.md) 判定 L0、L1 或 L2，并只加载该级允许的引用。

#### Scenario: L0 概念咨询
- **WHEN** 用户仅要求解释、定位或对比方案，且不修改仓库、不交付工单
- **THEN** 直接答复；不读实施/界面/交付流程，不做版本检查，不占用，不发起「待你确认」或一分钟选择。

#### Scenario: L1 明确单点小改
- **WHEN** 范围明确的文案、配置、局部逻辑或有同端同类参考的界面微调，且不改业务规则、跨模块 API 或架构
- **THEN** 走实施轻量路径：影响检查与最小验证；不建 OpenSpec 全套；用户未要求交付时不自动跑完整交付链。

#### Scenario: L2 正式开发交付
- **WHEN** 新能力、跨模块、规则或 API 变化、空白工程或技术栈变化、正式工单开发交付，或用户要求完整流程
- **THEN** 沿用正式实施 → 测试 → 交付主链，并按需加载对应引用。

#### Scenario: 执行中上调级别
- **WHEN** L1 进行中发现跨端范围、规则或 API 变化、无可用界面参考或验收不清
- **THEN** 升到 L2 或触发 Figma 门禁，简短告知用户；不因赶时间下调级别。

## MODIFIED Requirements

### Requirement: 正式开发以可追溯工单为入口

体系 SHALL 将 **L2 正式**功能和 Bug 关联至工单，至少包含诉求、影响范围和可检查的验收条件；聊天可用于澄清。新能力、业务规则变化、跨模块或接口变更使用完整 OpenSpec；局部行为恢复使用复现、方案和回归证据，发现规范错误或缺失时补充对应规范。**L0** 不创建工单交付；**L1** 无编号的明确小修可不建完整规格，有编号则领取后按轻量路径修改。

#### Scenario: 轻量任务不生成重复材料
- **WHEN** 任务是 L0 咨询、一次性连接验证、无行为变化的小文字修正，或符合 L1 的明确单点小改
- **THEN** 允许简化或跳过完整工单/规格/设计流程，保留适用的任务依据与检查结果；不能借此绕过 L2 实际业务变更的验收。

### Requirement: 新界面与弹窗按门禁决定是否 Figma 原型

体系 SHALL 对界面任务先核对同端同类参考与现行标准，再按 [是否需要 Figma 原型](../../../../../skills/personal-dev/references/ui-design.md#是否需要-figma-原型) 判定。仅在无可用同端参考、同端标准不一致且本任务须先定视觉口径、或客户/用户明确要求时，SHALL 制作可编辑 Figma 原型并关联具体文件或节点，用户选择或按一分钟策略采用具体版本后继续业务界面实现。有可用同端参考且标准一致时，SHALL 跳过原型，仍保留视觉依据与最终视觉验证。用户明确本任务不用生成 Figma 原型时记录范围后豁免。具体执行见 [界面一致性、原型与验收](../../../../../skills/personal-dev/references/ui-design.md)。

#### Scenario: 单字段弹窗且有现成同类参考
- **WHEN** 新弹窗只有单个输入框，目标应用已有可用同端同类参考且标准一致
- **THEN** 记录视觉依据后直接实现，不强制创建 Figma 原型；仍完成源码级一致性核对。

#### Scenario: 无参考或标准不一致或客户要求
- **WHEN** 目标应用找不到可用同类参考，或同端标准冲突须先定口径，或客户/用户明确要求 Figma
- **THEN** 先制作可编辑原型并按统一策略取得版本决定后实现，不直接跳过原型。

#### Scenario: 原型尚未确认
- **WHEN** 门禁判定需要原型，原型完成并检查后已展示推荐版本，但用户尚未回复
- **THEN** 标为待推荐选择，真实满 60 秒并核对消息及前置条件后按默认策略采用；记录决定来源，不能记为用户亲自验收。

#### Scenario: 用户仅要求代码完成后再看
- **WHEN** 门禁已判定需要 Figma，用户催促实现或要求完成代码后再看，但未明确不用 Figma 原型
- **THEN** 提供具体原型并确认，不把延期验收视为原型豁免或批准。

#### Scenario: 用户明确不生成原型
- **WHEN** 用户明确本任务不用 Figma 原型
- **THEN** 记录本任务的豁免范围后继续，不重复请求相同豁免，不推广到后续任务。

### Requirement: 提问默认启用一分钟推荐选择

体系 SHALL 在 **L1 / L2** 每题提供推荐答案、理由及主要影响；需要事实的题提供核实路径。进入 L1 / L2 后默认启用推荐选择，无需单独开启；**L0 不适用**。保留用户明确关闭、必须等待及暂停指令。对工作流提问（含门禁判定需要时的 Figma、重要选型、修改范围及测试责任），在发问时告知推荐及默认行为，真实等待 60 秒并检查最新回复、已有授权及必要前置条件后才可采用推荐。具体适用边界与计时唯一维护于 [提问推荐与一分钟默认选择](../../../../../skills/personal-dev/references/planning.md#提问推荐与一分钟默认选择)。不得将默认选择记为用户明确批准。

#### Scenario: L0 不适用一分钟选择
- **WHEN** 任务判定为 L0 咨询
- **THEN** 不发起「待你确认」、不播放提示音、不启用 60 秒默认选择。

#### Scenario: L1 或 L2 关键决定仍用统一策略
- **WHEN** L1 / L2 任务需要用户决定范围、选型或门禁判定需要的 Figma 版本，且策略未关闭
- **THEN** 展示推荐与超时说明，按既有 60 秒规则处理；L0 边界不削弱本场景。
