# 阶段 2 扩展：按工程检查与选择更新

用户已确认方案并授权实施；继续现有草稿分支，不合并 main。沿用 Python 标准库与现有事务安装器。

## 设计与边界

- 固定来源为个人 GitHub 仓库 main；安装记录完整 commit。开发分支领先 main 时报告 ahead，不建议降级；历史分叉或来源未知时不自动提出可安装候选。
- 完整接入分发本地 CLI 运行时到 Skill 的 scripts 目录。每次新任务由 Skill 调用 check-update，按工程缓存 24 小时。没有宿主钩子或后台服务，不宣称打开应用即保证触发。
- check-update 可联网、只写忽略目录中的检查状态；不改受管文件，不执行远端代码。失败返回不可检查，沿用本地规则。只有 force 显式检查绕过缓存。
- 提示包含安装版本、目标提交、变更摘要及比较链接。稍后提醒推迟 24 小时，跳过只针对具体提交；推荐本次沿用，下一任务前再更新。无回复不自动安装。
- update 必须提供已展示的完整 revision；默认下载到临时目录并预览，--apply 才写入。执行当前受信任安装器，不运行下载的脚本；校验协议、Git 对象摘要、路径、文件数量及大小。审批期间 main 前进仍安装原候选。
- 选择、候选与当前安装版本绑定。使用工程写锁和现有事务恢复；出现本地改动或并发变化拒绝覆盖。旧 manifest 可通过已审阅版本重新 init 补充 source。更新后下一任务加载新规则。
- 不新增 npm 包、插件自动更新、定时调度、全机升级或跨宿主自动发现保证。私有仓库和多渠道留待另行设计。

## 文件职责与执行顺序

1. `tests/test_updates.py`：先建立真实临时工程和本地 Git 历史夹具，失败测试覆盖版本来源、缓存、离线、版本前后关系、选择、固定候选、冲突、恢复与自包含 CLI。
2. `scripts/pda/source.py`：来源常量、提交校验、本地来源识别及受管运行时清单。`scripts/pda/install.py` 分发运行时并记录来源；`transaction.py` 扩展准确恢复清单。
3. `scripts/pda/remote.py`：固定 GitHub API 来源、有限超时和响应体积、版本比较、按提交获取并校验候选文件；不执行其内容。
4. `scripts/pda/updates.py`：检查与选择状态、每日节流、版本关系、预览及应用。`scripts/pda.py` 增加 check-update/update/skip-update/remind-later 参数校验。
5. Skill 新任务入口与 `references/updates.md` 只描述触发及用户流程；安装文档集中说明命令、bootstrap、恢复与限制。规范新增对应场景。
6. 验证完整 unittest、OpenSpec、链接、独立审查；在合成工程验证跨复制、升级/恢复及真实 GitHub 只读检查，再升级已接入工程，提交推送草稿分支。
