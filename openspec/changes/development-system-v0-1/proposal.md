# 个人开发体系第一版

## Why

上游技能已经提供需求澄清、实现、测试和复盘能力，但安装这些技能并不能形成一致的开发流程。它们可能重复触发、生成多套规格，且缺少工程接入、授权、升级和行为验证约定。

第一版建立可复用的流程和边界，覆盖空白工程建设与已有工程维护，并在真实任务中逐步验证。

## What Changes

- 以统一任务入口协调设计、执行和独立审查，按需调用精选上游能力。
- 第一版适配 Codex、Cursor；Claude 暂缓，技术栈由每个工程的大需求决定。
- 规范 Gitea 工单、Figma 验收、任务分支和 worktree、PR、主分支回归及 Tag 触发 Drone 打包。
- 分层管理规则、工程目录、临时产物、真实凭据和知识沉淀。
- 设计独立的工程初始化与升级入口，区分 Skill、CLI、插件、MCP 和宿主 Agent 配置。
- 设计夜间增量复盘、可查看报告和人工审核流程。

## Capabilities

### New Capabilities

- `development-lifecycle`：从需求与选型到开发、验收、合并和打包的状态与授权。
- `workspace-governance`：规则与文档归属、目录、秘密信息及文件生命周期。
- `capability-distribution`：初始化、上游适配、依赖可追溯、安装升级和跨工具验收。
- `knowledge-retrospective`：工程知识、通用能力提炼、夜间复盘报告与恢复。

### Modified Capabilities

无。本仓库尚无已交付的长期能力基线。

## Impact

阶段 1 落地设计基线和维护入口；阶段 2 增加本地安装器、共享 Skill 与工程配置，并在隔离试点验证。当前实现与限制见仓库 README，不代表整个开发体系或定时任务已完成。上游候选来源已记录，完整依赖及行为仍需后续验证。

试点输入由用户确认：zkxw 的集成主分支为 `V2.0`；已完成 Gitea 与 Drone 的 Tag 打包配置，该流水线沿用，不作为本次复查或修改对象。该特例不能作为其他工程已完成接入的证据。

## Delivery Milestones

| 阶段 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 设计基线 | 本变更、维护入口和任务记录 | 规则一致、链接有效、约定可追溯 |
| 2. 最小接入 | 工程配置、精选能力路由、Codex/Cursor 入口和初始化工具 | 干净安装、重复执行、冲突保留和失败恢复通过 |
| 3. 场景验收 | 空白工程、zkxw Bug 与功能变更的实际证据 | 目标工具行为验证完成；新工程 Drone 测试 Tag 的产物可获取 |
| 4. 复盘启用 | 复盘能力、报告与本机 23:00 调度 | 手动试跑报告经用户核对；调度创建并验证 |
| 5. 首次发布 | 版本、依赖来源、验证证据和升级说明 | 满足贡献指南；发布和推送 Tag 已获授权 |

阶段 2–4 各自编写可执行计划后实施；本次 [任务文件](tasks.md) 仅追踪阶段 1，完成它不代表整个变更可归档。
