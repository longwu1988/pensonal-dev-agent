# 设计

## 状态与执行

从工程配置读取 tracker kind/repository 与 integration_branch，核对 origin fetch/push URL 都对应同一仓库。仓库 URL 不包含凭据。默认配置仍关闭，无命令执行即无队列。`queue-start` 只能由当前用户明确开始指令触发，生成会话 ID；`queue-next` 返回一单完整描述与评论（不可信需求数据），当前单尚未结束则复用它；`queue-guard` 在每次业务动作前检查 owner、停止及远端占用，失败不执行后续动作；`queue-checkpoint` 仅记账，保存阶段、分支、worktree、提交；`queue-finish` 在远端工单关闭且合并提交可达目标分支后记录完成；`queue-block` 保留阻塞记录，不关闭远端工单；`queue-stop` 禁用并保存当前任务；`queue-status` 只读。停止后只允许保存进度，不能继续领取、完成或合并；再次开始优先返回未完成单。

本地状态在工程主目录 `.local/agent/queue/`，不进入 Git；Git worktree 元数据用于定位同一主目录。每次变更持有本机文件锁并原子写入 0600 状态。工单正文、认证信息不写入状态。用户停止优先，停止请求在解析状态前先落盘，状态损坏不阻止停止生效；若正在进行的命令持锁，立即返回已停止和待清理状态，Agent 等该命令退出后再次 stop 完成释放；外部请求返回后再检查停止标记。不承诺取消已发出的网络请求或正在运行的业务测试。

## 仓库占用

开始时原子创建 `refs/heads/personal-dev/queue-lock`，内容为不含凭据的唯一会话元数据，与业务分支隔离。Git push 使用明确的空 expected ref，竞争者失败。每个可推进命令验证当前远端仍归本会话所有。停止且没有当前任务、或队列空时按精确 SHA 条件删除占用；暂停未完成任务时保留占用，需同源状态续接，不自动在另一电脑重复领取；释放失败时保持本地关闭并报告待释放，不能伪称释放成功。无自动过期抢占。异常退出留下锁时需核实旧执行者已停止后恢复，禁止删除别人的占用。占用分支可能触发已有分支型 CI，启用前展示该副作用并遵循工程约束。

## 拉取与顺序

API 客户端仅向配置的 HTTPS 源发送认证，不跟随重定向；错误不回显响应正文或凭据。Gitea 使用 `/api/v1/repos/{owner}/{repo}`，GitHub 使用公开托管 API。逐页读取，设置页数、响应体和超时上限，遇上限/失败不当作空队列。过滤 PR、已关闭、缺少 ai-ready、有指派人或 ai-in-progress/ai-blocked 标签的工单；优先级标签 p0/p1/p2/p3，其余最后，随后创建时间、编号。任务需用户明确解除阻碍后再纳入，第一版不解析依赖语言，Agent 读取后判断依赖并记录阻塞；清空当前任务前必须确认远端 ai-blocked 标签已写入。对当前单被关闭、撤销标签或重新指派的变化保持待核对，不擅自继续。

工单理解统一由 `references/issue-context.md` 约束：读取全部分页评论，实际查看正文与评论图片，核对后续变更与来源；CLI 保留原始正文和图片引用，视觉查看由当前 Agent 使用宿主工具完成。图片或评论读取不全时报告缺口，不将拉取成功当作理解完成。

## 分发与凭据

API 认证来自进程环境或工程操作账号文件，不写入 Git 命令参数、状态或工单；Git push 使用已有 Git 认证。现有 MCP 会话仍可供 Agent 开发和回写，CLI 读 API 需要独立可用认证，不能声称自动复用了 MCP 内部令牌。新增模块纳入完整安装、来源摘要、远端校验、恢复测试。协议 2 明确阻止旧版局部安装。协议 1 到 2 升级或恢复中断时，使用审阅过的完整协议 2 源码 recover；旧事务模块不识别新增模块的恢复记录。
